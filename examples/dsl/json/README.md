# JSON Configuration Format for UnitAPI DSL

JSON (JavaScript Object Notation) is a lightweight data-interchange format that is easy for humans to read and write and easy for machines to parse and generate. It's a widely used format for configuration files and APIs.

## Features

- Standard, language-independent data format
- Simple syntax with key-value pairs
- Supports nested structures
- Widely supported across programming languages
- Good for machine-generated configurations

## Example

This directory contains an example JSON configuration for UnitAPI DSL:

- `example.json` - Microphone device configuration demonstrating JSON syntax

## Structure

A typical JSON configuration for UnitAPI includes:

1. **Version** - The version of the configuration format
2. **Extensions** - Definitions of device capabilities and requirements
3. **Devices** - Definitions of physical or virtual hardware
4. **Pipelines** - Workflows that connect devices and process data

## Testing

You can test the JSON configuration using the provided `test.py` script:

```bash
# Run the test script
python test.py

# Test with a different configuration file
python test.py --config other_config.json

# Validate without executing
python test.py --dry-run

# Convert to another format
python test.py --convert-to yaml
```

## When to Use JSON

JSON is a good choice when:

- You need a widely supported, standard format
- Your configuration is generated by another program
- You're working with web applications or APIs
- You need to parse the configuration in multiple languages
- You want a format with a simple, well-defined structure

## Syntax Highlights

```json
{
  "version": "1.0",
  
  "extensions": [
    {
      "name": "device_type",
      "version": ">=1.0.0",
      "config": {
        "parameter1": "value1",
        "parameter2": "value2"
      }
    }
  ],
  
  "devices": [
    {
      "id": "device-id",
      "device_type": "device_type",
      "capabilities": ["capability1", "capability2"]
    }
  ],
  
  "pipelines": [
    {
      "name": "pipeline-name",
      "source": "device-id",
      "steps": [
        {
          "action": "action-name",
          "params": {
            "parameter1": "value1",
            "parameter2": "value2"
          }
        }
      ]
    }
  ]
}
```

## Limitations

- JSON doesn't support comments natively
- All strings must be enclosed in double quotes
- Trailing commas are not allowed
- More verbose than some other formats like YAML
